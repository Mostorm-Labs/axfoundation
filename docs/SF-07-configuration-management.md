# SF-07 — 配置管理规范

- **状态：** 提案中
- **版本：** 1.0
- **负责人：** 软件架构
- **关联规范：** SF-01、SF-06、SF-08、SF-09、SF-10

## 1. 目的

为不同环境和软件版本提供可预测的配置行为，将配置与应用二进制分离，并保护敏感信息。

## 2. 配置类别

应区分：
- 内置默认配置；
- 部署/安装包默认配置；
- 机器/设备配置；
- 用户偏好配置；
- 组织/管理员策略；
- 远程托管配置；
- 密钥和凭据。

不要将所有配置混在一个所有权不清晰的扁平文件中。

## 3. 配置优先级

每个产品必须定义配置优先级。推荐默认顺序（从低到高）：

`内置默认值 < 部署默认配置 < 机器/设备配置 < 用户偏好 < 管理员策略`

远程策略的优先级必须明确；远程配置不得静默覆盖信任级别更高的本地安全约束。密钥应单独管理，不能作为普通配置值处理。

## 4. Schema

配置必须具有 Schema 或等效校验契约，至少说明：
- Key 和数据类型；
- 默认值；
- 允许范围/枚举；
- 必填/可选；
- 负责人和作用范围；
- 敏感级别；
- 引入/弃用版本；
- 迁移行为。

无效配置必须产生可诊断错误，并采用安全回退或明确拒绝。不得通过改变行为的隐式强制转换来处理配置。

## 5. 持久化与迁移

配置格式必须独立于产品版本进行版本管理。迁移应该是确定性的、幂等的且可测试。在安全可行时保留未知 Key。如果配置无法被安全解释，应保留原始配置并报告问题，而不是覆盖它。

用户数据、运行状态和配置应该使用不同的存储位置及备份策略。

## 6. 密钥管理

密码、API Token、私钥和长期凭据不得以明文存储在普通配置文件中。应使用平台凭据存储或经批准的密钥管理服务。密钥值不得出现在日志、崩溃报告和诊断包中。

## 7. 远程配置与功能开关

远程配置应该用于受控发布、环境配置和功能开关，而不是替代稳定的本地契约。

要求：
- 认证传输并验证服务端身份；
- Schema/版本校验；
- 明确作用范围（产品、租户、设备群组）；
- 过期时间/TTL 和过期配置行为；
- 变更审计记录；
- 回退到最近一次可用配置；
- 离线时采用安全默认值。

远程 Feature Flag 不得成为安全关键行为的唯一保护措施。本地授权和安全检查仍然有效。

## 8. 配置变更行为

必须定义配置变更是立即生效、组件重启生效还是应用重启生效。配置更新应该是原子的。多个写入者并发时，必须使用锁或明确的单写入者规则。

## 9. 验收清单

- [ ] 配置类别和优先级已记录。
- [ ] 存在 Schema 校验和默认值。
- [ ] 配置版本及迁移策略已定义。
- [ ] 密钥使用安全存储。
- [ ] 远程配置具有认证、过期和回滚行为。
- [ ] 日志和诊断包对敏感信息进行脱敏。
