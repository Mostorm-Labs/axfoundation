# SF-07 — 配置管理规范

- **状态：** 提案中
- **版本：** 1.0
- **负责人：** 软件架构
- **关联规范：** SF-01、SF-06、SF-08、SF-09、SF-10

## 1. 目的

为不同环境和软件版本提供可预测的配置行为，将配置与应用二进制分离，并保护敏感信息。

## 2. 配置类别

应区分：
- 内置默认配置；
- 部署/安装包默认配置；
- 机器/设备配置；
- 用户偏好配置；
- 组织/管理员策略；
- 远程托管配置；
- 密钥和凭据。

不要将所有配置混在一个所有权不清晰的扁平文件中。

### 2.1 配置所有权与存储范围

每组持久配置必须有一个权威所有者和明确的写入入口。应用界面、Launcher、命令行及控制面若操作同一组配置，应使用该所有者的契约。所有权迁移时要定义交接版本和兼容方式，避免两个组件长期各自保存并相互覆盖。

需要在同一设备的不同登录账户间共享的配置，应使用权限明确的机器数据目录。只属于当前用户的偏好应使用用户目录。安装和更新应分别处理程序文件、配置、身份与凭据。参见 [SF-05](SF-05-installation-and-update.md) 和 [SF-08](SF-08-runtime-foundation.md)。

## 3. 配置优先级

每个产品必须定义配置优先级。推荐默认顺序（从低到高）：

`内置默认值 < 部署默认配置 < 机器/设备配置 < 用户偏好 < 管理员策略`

远程策略的优先级必须明确；远程配置不得静默覆盖信任级别更高的本地安全约束。密钥应单独管理，不能作为普通配置值处理。

支持命令行或环境变量的产品，应声明它们在相应配置范围内的优先级，以及每项是本次运行覆盖还是授权保存。明确传值与省略参数应分别处理。省略时继续按其他来源求值。参数校验、预览及错误值回退不得被当成用户保存意图。只有契约明确列出的有效参数才能触发保存。

## 4. Schema

配置必须具有 Schema 或等效校验契约，至少说明：
- Key 和数据类型；
- 默认值；
- 允许范围/枚举；
- 必填/可选；
- 负责人和作用范围；
- 敏感级别；
- 引入/弃用版本；
- 迁移行为。

面向使用者的配置清单应额外列出可配置入口、存储范围、首次启动行为及生效时机。列出只读状态、会话设置和废弃参数时，应标明它们的适用范围。

无效配置必须产生可诊断错误，并采用安全回退或明确拒绝。不得通过改变行为的隐式强制转换来处理配置。

## 5. 持久化与迁移

配置格式必须独立于产品版本进行版本管理。迁移应该是确定性的、幂等的且可测试。在安全可行时保留未知 Key。如果配置无法被安全解释，应保留原始配置并报告问题，而不是覆盖它。

用户数据、运行状态和配置应该使用不同的存储位置及备份策略。

支持配置文件写入时，应采用同卷原子替换或平台等效事务，并定义失败后如何保留已确认的数据。支持备份恢复或重置时，应记录可用条件、操作范围、需重启的字段及失败行为。遇到未来 Schema 或无法安全迁移的数据时，应保留原文件并阻止不兼容写入。恢复配置应与删除身份、凭据或用户内容分别授权。

## 6. 密钥管理

密码、API Token、私钥和长期凭据不得以明文存储在普通配置文件中。应使用平台凭据存储或经批准的密钥管理服务。密钥值不得出现在日志、崩溃报告和诊断包中。

## 7. 远程配置与功能开关

远程配置应该用于受控发布、环境配置和功能开关，而不是替代稳定的本地契约。

要求：
- 认证传输并验证服务端身份；
- Schema/版本校验；
- 明确作用范围（产品、租户、设备群组）；
- 过期时间/TTL 和过期配置行为；
- 变更审计记录；
- 回退到最近一次可用配置；
- 离线时采用安全默认值。

远程 Feature Flag 不得成为安全关键行为的唯一保护措施。本地授权和安全检查仍然有效。

## 8. 配置变更行为

必须定义配置变更是立即生效、组件重启生效还是应用重启生效。多个写入者并发时，必须使用锁或明确的单写入者规则。

### 8.1 变更结果与并发

- 当产品支持运行时控制时，应分别报告请求的配置值、实际生效值、已保存值和待重启项。
- 写入契约应明确区分临时应用与持久保存，并分别返回应用和保存结果。成功接收请求、完成保存和应用到当前进程是不同阶段。接口不支持的保存请求应明确失败。
- 支持多个控制客户端时，应提供配置修订或等效的并发保护。过期写入须被拒绝或按明确合并规则处理。跨进程重启可能使旧请求失效时，应提供实例标识或等效机制。

## 9. 验收清单

- [ ] 配置类别和优先级已记录。
- [ ] 已定义唯一写入方、存储范围与旧入口兼容行为。
- [ ] 存在 Schema 校验和默认值。
- [ ] 配置版本及迁移策略已定义。
- [ ] 可区分临时修改、持久保存以及待重启状态，并已验证恢复和并发写入。
- [ ] 密钥使用安全存储。
- [ ] 远程配置具有认证、过期和回滚行为。
- [ ] 日志和诊断包对敏感信息进行脱敏。
