# Windows 接收端参考实践

本示例用于编写采用记录和验证计划，适用于由 Launcher 启动、带本地控制面的 Windows 桌面接收端。项目可按实际运行环境选用这些做法，采用状态由项目的验证证据确认。

| 领域 | 参考做法 | 可复核证据 |
| --- | --- | --- |
| [版本分配](../SF-01-software-versioning.md) | 权威计数保存在版本文件。发布流水线可在单独的元数据分支上原子预留 BUILD。应用目标使用预留版本，测试目标只读取版本。 | 并发分配测试、失败后计数、包内版本与 EXE 文件版本对照。 |
| [依赖与 CI](../SF-03-build-and-cicd.md) | 在干净递归检出上恢复锁定依赖，验证生成代码和层间依赖。对影响运行行为的定制库，从测试进程核对已加载模块。 | 产品与工具提交、归档摘要、边界检查、实际加载模块与测试结果。 |
| [发布与分发](../SF-04-release-and-distribution.md) | 例如 Tag `v2.4.1.1024` 指向被验证的产品提交。该版本包含安装包和配套工具，声明各文件摘要。测试和正式发布通过渠道区分。 | Tag 对应的产品提交、发布记录、文件摘要和目标渠道结果。 |
| [安装与启动](../SF-05-installation-and-update.md) | Launcher 调用目标版本的脚本。已知版本可在启动前进行只读检查。启动后分别确认进程、控制面和接收业务。 | 版本不匹配、旧参数、探测副作用、升级前后实际版本及业务状态。 |
| [日志与调试](../SF-06-logging-and-diagnostics.md) | 文件日志、详细级别和内部调试入口单独设置。诊断包仅收集白名单内的文件，限制预算并支持本地预览。 | 日志队列过载、目录不可写、延迟预算、归档范围和脱敏样本。 |
| [配置](../SF-07-configuration-management.md) | 每组偏好由一个组件持久化。控制面回报本次生效与下次启动的值。存储路径按机器或用户范围决定。 | 首次启动、切换账号、临时修改、显式保存、重启读回及恢复测试。 |

## Windows 平台约束

- Windows `FILEVERSION` 的四段都是 16 位整数，每段上限为 65535。分配编号时应预留溢出处理路径。参见 [VERSIONINFO resource](https://learn.microsoft.com/windows/win32/menurc/versioninfo-resource)。
- MSI 比较 `ProductVersion` 时只使用前三段，第一、二段各自上限为 255。若 `2.4.1.1024` 和 `2.4.1.1025` 使用同一 MSI 产品版本，需覆盖包的升级规则及目标 EXE 版本检查。参见 [MSI ProductVersion](https://learn.microsoft.com/windows/win32/msi/productversion)。
- 设备公用配置可位于 `%PROGRAMDATA%\<vendor>\<product>\settings`，用户偏好可位于 `%LOCALAPPDATA%\<vendor>\<product>`。使用平台已知目录，并由安装器配置所需账户权限。验证普通升级、卸载重装与账号切换的读写行为。参见 [Windows Shell 安装与数据位置](https://learn.microsoft.com/windows/win32/shell/sec-shell)。

## 启动和配置的验证场景

| 场景 | 预期结果 |
| --- | --- |
| 没有保存值，旧 Launcher 省略可选参数 | 使用应用默认值。 |
| 旧 Launcher 显式传参 | 识别受支持的旧名称，按启动契约决定优先级和保存行为。 |
| Launcher 持有旧偏好，应用接管存储 | 应用按已声明的优先级读取自己的配置。新版 Launcher 停止重复发送已交接的偏好。 |
| 启动工具向不支持探测的旧 EXE 下发选项 | 使用该版本配套的兼容路径，报告无法验证的请求。 |
| 控制面请求临时改动，随后重启 | 当前生效值可变。下次启动按已保存值和启动参数恢复。 |
| 保存重启项 | 报告保存成功及待重启，重启后核对实际生效值。 |
| 配置损坏、写入中断或旧版遇到新 Schema | 根据契约恢复有效备份或进入明确的回退状态，保护不能解释的文件。 |

可逐步采用上述规则。已有 Launcher 作为配置所有者的产品应声明此行为，并在应用控制面明确拒绝不支持的保存请求。由应用接管时要验证旧入口、安装目录替换、多个账户和回滚路径。对依赖实体设备的接收行为，采用记录应分别列出合成测试和真机证据。参见 [SF-10](../SF-10-compatibility-and-testing.md)。

## 日志验证示例

实时接收端可将单日志段限制为 10 MiB，并同时限制保留天数、文件数、总容量和待写队列。启用详细日志时，用合成流量验证队列饱和后的丢弃计数和接收延迟。测试还应覆盖不可写目录、启动早期崩溃，以及诊断包达到大小上限时记录的省略信息。项目采用记录应填写实测预算和适用场景。
